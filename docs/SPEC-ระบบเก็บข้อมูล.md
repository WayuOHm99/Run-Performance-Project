## 2. สถาปัตยกรรม — Plan B (ไม่ใช้ Anthropic API)

```
นักกีฬาส่งรูป + พิมพ์ RPE ในกลุ่มไลน์
        ↓  webhook (ฟรี)
Supabase Edge Function — จับกลุ่มด้วย timestamp, รู้ว่าใครส่ง
        ↓
```

**หมายเหตุสำคัญ:** bot ถูกเชิญเข้ากลุ่มไลน์ทีมที่ใช้อยู่เดิมได้ นักกีฬาไม่ต้องเปลี่ยนอะไรเลย

## 3. กฎเหล็ก 3 ข้อ

### 3.1 แยก "อ่านได้" ออกจาก "ต้องตัดสิน"

| ดึงอัตโนมัติได้ | ห้ามให้ระบบเขียนเอง |
| --- | --- |
| ระยะ เวลา เพซ HR splits โซน power cadence running dynamics แคลอรี่ อุณหภูมิ | ประเภทเซสชัน · สถานะ (ตามแผน/เกินแผน) · โน้ตโค้ช · คำสั่งถัดไป |

### 3.2 ไม่เห็น = `null` ห้ามเดาเด็ดขาด

โมเดล vision มีนิสัยเติมตัวเลขที่ "ดูสมเหตุสมผล" เมื่ออ่านไม่ชัด ในระบบโค้ช ตัวเลข HR ที่กุขึ้นมานำไปสู่คำสั่งซ้อมที่ผิดได้ — `null` ที่ซื่อสัตย์ดีกว่าเสมอ

ห้ามคำนวณค่าที่ไม่ได้เห็นด้วย (เช่น ระยะรวมจากผลบวกของ laps) ให้ทำในขั้นตอนหลัง และติดป้ายว่าเป็นค่าคำนวณ

### 3.3 แยก "อ่านจากตาราง" ออกจาก "อนุมานจากกราฟ"

ความน่าเชื่อถือไม่เท่ากัน ต้องติดป้าย `source: "table" | "chart" | "inferred"`

## 5. การจับกลุ่มกิจกรรม (ยากกว่า OCR)

รูป 20 ใบอาจเป็น 1 หรือ 2 กิจกรรม ถ้าแบ่งผิดตัวเลขจะปนกันหมด

**สัญญาณที่ใช้ได้ (เรียงตามความน่าเชื่อถือ):**

1. **เวลาเริ่มกิจกรรมในรูป** (เช่น "17 ก.ค. @ 06:32" vs "@ 07:18") — แม่นที่สุด
2. **timestamp ของข้อความไลน์** — ในระบบจริงจะมี
3. **เวลาแคปหน้าจอมุมบนซ้าย** — รูปชุดเดียวกันมักห่างกันไม่กี่นาที
4. ~~ชื่อไฟล์~~ — ใช้ไม่ได้ในระบบจริง (LINE ตั้งชื่อสุ่ม)

**กติกาที่ตกลงแล้ว: 1 กิจกรรม = 1 เรคคอร์ด Notion เสมอ**
ให้ Notion rollup รวมยอดรายวัน/สัปดาห์เอง — เพราะต้องแยก warm-up ออกจาก main session ได้เวลานับจำนวนเซสชันคุณภาพ

> ⚠️ ข้อมูลเดิมยังไม่สอดคล้อง: เรคคอร์ด "แดน 17 ก.ค." ยุบ WU + Main รวมเป็นเรคคอร์ดเดียว (11.63 กม.) ควรแยกเป็น 2 เรคคอร์ดตามกติกาใหม่

## 6. บริบทที่ต้องดึงมาทุกครั้ง (บทเรียนราคาแพง)

**ห้ามประเมินเซสชันจากข้อมูลวันนั้นวันเดียว** — พิสูจน์แล้วว่าพลาดจริง (กรณีพี่เก้า 17 ก.ค. ที่ถูกบันทึกว่า "ตามแผน" ทั้งที่ฝ่าคำสั่งพักจากวันก่อนหน้า)

ทุกครั้งที่ประมวลผลเซสชันใหม่ ต้องดึง:

1. **คำสั่งค้างของโค้ช** จากเรคคอร์ด 3-7 วันย้อนหลัง (โดยเฉพาะคำสั่งพัก/ห้าม)
2. **โหลดรวม 7 วันย้อนหลัง** ของนักกีฬาคนนั้น (ระยะ, จำนวนเซสชันคุณภาพ, วันพัก)
3. **โซนล่าสุด** จากผลเทสของคนนั้น (VDOT / LTHR / LT1-LT2)
4. **จุดเฝ้าระวังรายบุคคล** จาก CLAUDE.md
