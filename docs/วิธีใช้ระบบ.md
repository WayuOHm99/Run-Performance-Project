## 🔐 สำรองนอกเครื่องและกู้คืน

- `Run-Performance-OffsiteBackup` รัน 22:30: รับเฉพาะ SQLite snapshot ที่ตรวจผ่าน แล้วเข้ารหัสด้วย Restic ก่อนอัปโหลดไป private GitHub Release (เก็บ 3 รุ่นล่าสุด)
- รหัส Restic ฝั่งเครื่องเก็บด้วย DPAPI CurrentUser; ฝั่งกู้คืนเก็บใน GitHub Actions secret — ไม่มีไฟล์รหัสผ่าน plaintext
- `Run-Performance-RestoreDrill` รันทุก 4 สัปดาห์: restore ลงพื้นที่ชั่วคราว ตรวจว่าเป็น Garmin DB ที่มี schema/ข้อมูล/ความสดไม่เกิน 7 วัน และเปิด Dashboard กับสำเนาได้จริง โดยไม่ทับฐานใช้งาน
- `Run-Performance-SystemHealth` ส่งทุก 2 ชั่วโมงเฉพาะเวลา/status/จำนวน OK/WARNING/ERROR; ไม่มีชื่อหรือค่าของนักกีฬา แล้ว GitHub Actions ตรวจความสดทุกชั่วโมง ถ้าพังจะเปิด GitHub Issue `Run Performance system alert` เพียงใบเดียว; เมื่อหายจะ comment หลักฐาน recovery แล้วปิดให้อัตโนมัติ

ติดตั้ง/ซ่อมทั้งชุดด้วย PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\setup_offsite_backup.ps1
```

เปิด GitHub Actions → `Restore encrypted offsite backup` → Run workflow เพื่อทดสอบแบบ validate-only ได้โดยไม่สร้าง artifact. ถ้าเครื่องหลักหายและต้องดาวน์โหลดไฟล์จริง ให้ติ๊ก `upload_recovered_files`; ระบบจะตรวจ SHA-256, restore และสร้าง private artifact ให้ดาวน์โหลด 7 วัน หลังดาวน์โหลดเสร็จให้ลบ workflow run/artifact ก่อนกำหนดได้ถ้าไม่ต้องใช้แล้ว

ตรวจว่าตารางงานใน Windows ยังตรงกับแผนแบบ read-only:

```powershell
garmin\.venv\Scripts\python.exe garmin\scripts\verify_scheduled_tasks.py --json
```

หลัง Windows Update/restart ให้ log in ผู้ใช้เดิมหนึ่งครั้ง งานที่พลาดจะตามเก็บด้วย `StartWhenAvailable`/catch-up. ระบบตั้งใจไม่เก็บรหัสผ่าน Windows และไม่เปิด auto-login; ก่อน log in จึงยังไม่ใช่ระบบ always-on.

ช่วง 01:00–08:00 Asia/Bangkok ถือเป็นเวลาที่โน้ตบุ๊กอาจหลับตามปกติ จึงไม่แจ้งเหตุเพียงเพราะ heartbeat เก่า แต่สถานะ error/ข้อมูลผิดรูป/เวลาในอนาคตยังแจ้งทันที; หลัง 08:00 จะกลับมาตรวจความสดตามปกติ.

### ระบบทำเองแค่ไหน

- **ทำเอง:** retry งานชั่วคราว, ตามเก็บรอบหลังตื่น/หลัง log in, กันงานชนกัน, แจ้งปัญหาใหม่ทันที, เตือนปัญหาเดิมซ้ำทุก 6 ชั่วโมง และส่งข้อความหายดีหนึ่งครั้ง
- **ต้องให้เจ้าของยืนยันก่อน:** สร้าง token ใหม่, เปลี่ยน secret/ตารางงาน/โค้ด, นำ backup มาทับ `garmin.db` จริง, หรือลบฐานข้อมูล/สำเนา ระบบทดสอบ restore ได้เฉพาะในพื้นที่ชั่วคราวและ AI ไม่มีสิทธิ์ข้ามขอบเขตนี้เอง
- ถ้าเป็นปัญหาเสี่ยงสูง ระบบต้องหยุดพร้อมหลักฐาน ไม่สุ่มแก้ฐานข้อมูลหรือ credential

## 🚨 เวลามีปัญหา

**Garmin ไม่อัปเดต / ข้อมูลค้าง** → เช็ค dashboard แท็บรวมทีม แถบ "sync ล่าสุด"

- 🔴 ค้างหลายวัน + มีแถบแดง "sync รอบล่าสุดล้มเหลว" → token เสีย ให้รัน `garmin\เพิ่มนักกีฬา.bat` ใหม่
- 🔴 ค้าง แต่ sync รอบล่าสุด**ผ่าน** (ไม่มีแถบแดง) → นักกีฬายังไม่เปิดแอป Garmin ให้นาฬิกา sync
- **ตัวเลขบนจอไม่ขยับ** → กดปุ่ม "รีเฟรชข้อมูลล่าสุด" ก่อน หน้าจอไม่รีเฟรชเอง
- toast เด้ง "sync ล้มเหลว" → เปิด log ของสายนั้นใน `C:\Backup\run-performance-logs\`: `garmin-sync-full.log` (รอบใหญ่ 08:00/21:00) / `garmin-sync-fast.log` (กิจกรรมทุก 15 นาที) / `garmin-sync-wellness.log` (ทุก 30 นาที) / `garmin-sync-reconcile.log` / `garmin-sync-deepsync.log`
- toast เด้ง "มีสายที่หยุดเดิน" → งานอัตโนมัติของสายนั้นไม่ได้รันมานาน เปิด Task Scheduler ดูว่างานยัง Ready อยู่ไหม แล้วรัน `scripts\setup_scheduled_tasks.ps1 -IncludeOptional` ซ้ำเพื่อซ่อมตารางงาน

**สคริปต์ขึ้น error สีแดง** → ก๊อปข้อความทั้งหมดมาให้ Codex อ่านและบอกวิธีแก้
